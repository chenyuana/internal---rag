# 表格人工复核门禁

混合解析及扫描法规解析会生成 `table_manual_review` 失败门禁。以下任一条件要求复核：保留的 OCR 块包含表格、OCR 路由输出表格、表格跨页、合并单元格计数非零，或现有检测发现结构/内容风险。检测不依赖文件名、源文件哈希或固定页码，样本修补不能清除原始 OCR 证据触发的复核要求。

任务进入 `needs_review`，QA 保存页码、原因和 `table_review_status=review_required`。解析结果继续保留，供既有原始 PDF、截图、页面及 Chunk 预览核对。当前按整个任务阻止发布，不做部分表格发布。

审核人员对照原图检查数字、行列对应、空白格及跨页完整性，必要时修正，再使用现有“人工确认无误”按钮显式放行。普通审核通过不能绕过失败门禁；既有审核历史记录审核人、时间和被放行门禁。审核后再次修改 Chunk 会清除审核放行状态。

QA 中的复核状态表示机器检测结果，最终人工结论以任务的 review 字段及 review_history.jsonl 为准。简单原生单页表格不新增此门禁，但仍受原有发布审核约束。

该改动作用于下一次解析/重建，未迁移历史产物、修改历史审核记录或撤回已发布内容。加载新代码后，历史文档需重新处理才能生成新门禁。

验证：表格门禁、混合/扫描解析测试 73 项通过；入库 API 测试包含显式放行及编辑后撤销放行。DRS 保存 OCR 证据触发 17 个表格页面复核（12、13、23–29、33、34、37–42）；这是离线证据验证，未重新请求 OCR。
